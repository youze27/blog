终端防御规避技术-4.对象通知

卷卷原创2026/10/27大约 11 分钟应急响应应急响应EDR终端防御与规避免杀对象通知

Windows 把进程、线程、文件都抽象成内核对象，用户态代码想操作它们，得先拿到句柄。句柄就是一把钥匙，对象通知则是配钥匙窗口的登记本：谁来配、配哪扇门、要开哪几个抽屉，都会记一笔。这一章讲的就是这本登记本怎么工作，以及攻击者怎么绕过它。

1. 句柄、对象与访问掩码

攻击者进程
  | OpenProcess(lsass_pid, PROCESS_VM_READ | PROCESS_QUERY_INFORMATION)
  v
内核对象管理器
  | 查 ACL
  | 触发对象回调（pre）
  v
EDR：目标是 lsass？要读内存？
  | 是 -> 从 DesiredAccess 里裁掉 PROCESS_VM_READ
  v
句柄表（编号 0x1A4）
  | ReadProcessMemory(0x1A4, ...)
  v
内核代劳读写目标进程内存

打开对象时要提交一份权限清单，叫 DesiredAccess。PROCESS_VM_READ 是读内存，PROCESS_CREATE_THREAD 是创建远程线程，PROCESS_ALL_ACCESS 是"能要的全要"。内核先按对象的 ACL 检查这份清单，再决定授予多少，授予的结果叫 GrantedAccess。ACL 相当于物业的准入规定，访问掩码则是你填的申请单。

对象通知站在"检查 ACL 之后、句柄返回之前"这个位置。pre 回调能改 DesiredAccess，post 回调能看到最终的 GrantedAccess。所以它像配钥匙窗口的安检：看你申请什么权限，不跟你进房间。

2. ObRegisterCallbacks

2.1 注册

OB_OPERATION_REGISTRATION ops = {0};
ops.ObjectType = PsProcessType;   // 也可以是 PsThreadType
ops.Operations = OB_OPERATION_HANDLE_CREATE | OB_OPERATION_HANDLE_DUPLICATE;
ops.PreOperation = OnPreOperation;
ops.PostOperation = OnPostOperation;

OB_CALLBACK_REGISTRATION reg = {0};
reg.Version = OB_FLT_REGISTRATION_VERSION;
reg.OperationRegistrationCount = 1;
reg.OperationRegistration = &ops;
// reg.Altitude 使用厂商分配的 altitude 字符串

ObRegisterCallbacks(&reg, &g_ObRegistration);
  • OB_OPERATION_HANDLE_CREATE：打开一个对象，生成新句柄。
  • OB_OPERATION_HANDLE_DUPLICATE：把已有句柄复制到另一个进程。
  • PsProcessType 和 PsThreadType 是最常用的两个对象类型，lsass 保护、远程线程拦截都靠它们。
  • 注销用 ObUnRegisterCallbacks，同样要在驱动卸载前完成。

2.2 pre 与 post 的分工

OB_PREOP_CALLBACK_STATUS OnPreOperation(PVOID ctx, POB_PRE_OPERATION_INFORMATION info)
{
    if (info->ObjectType == *PsProcessType &&
        info->Operation == OB_OPERATION_HANDLE_CREATE) {
        // info->Object 是目标 PEPROCESS
        // info->Parameters->CreateHandleInformation.DesiredAccess 是申请权限
        // 例如目标是 lsass.exe，就去掉读/写内存
        info->Parameters->CreateHandleInformation.DesiredAccess &=
            ~(PROCESS_VM_READ | PROCESS_VM_WRITE);
    }
    return OB_PREOP_SUCCESS;
}

pre 回调能改权限，post 回调只能看。这决定了 EDR 的典型做法：在 pre 阶段把危险权限裁掉，在 post 阶段记录"谁最终拿到了多少权限"。

为什么是裁剪，不是拒绝
对象回调的返回值只有成功，不能返回"拒绝"。把 DesiredAccess 清成 0，句柄照样创建成功，只是这个句柄什么都做不了。攻击者看到的不是"打开失败"，而是后续 ReadProcessMemory 失败，或者 dump 工具报错、生成 0 字节文件。

保安不能说"不给你配钥匙"，只能把钥匙上对应抽屉的齿磨平。钥匙照样交到你手里，但那个抽屉打不开。

2.3 altitude 与注册门槛

每个驱动注册时要填一个 Altitude，微软按厂商分配号段。装了多个安全产品时，同一操作上的回调按 altitude 排序执行，谁先看到、谁先裁剪由这个值决定。

不是谁都能注册
微软对进程、线程对象的回调注册加了限制：驱动必须通过微软的签名认证（反恶意软件级别），普通驱动调用 ObRegisterCallbacks 会失败。这既是 EDR 的护城河，也意味着攻击者想"自己注册一个回调来偷看"基本走不通，只能去打已有回调的主意。

3. 访问掩码

掩码值作用风险
PROCESS_TERMINATE0x0001结束进程√
PROCESS_CREATE_THREAD0x0002在目标进程创建线程√
PROCESS_VM_OPERATION0x0008分配、改保护属性√
PROCESS_VM_READ0x0010读目标内存√
PROCESS_VM_WRITE0x0020写目标内存√
PROCESS_DUP_HANDLE0x0040复制目标的句柄√
PROCESS_QUERY_INFORMATION0x0400查详细信息√
PROCESS_SUSPEND_RESUME0x0800挂起/恢复进程√
PROCESS_QUERY_LIMITED_INFORMATION0x1000查基本信息×
PROCESS_ALL_ACCESS0x1FFFFF所有权限√
THREAD_GET_CONTEXT0x0008读线程上下文√
THREAD_SET_CONTEXT0x0010改线程上下文√
THREAD_SUSPEND_RESUME0x0002挂起/恢复线程√
TOKEN_DUPLICATE0x0002复制令牌√
TOKEN_QUERY0x0008查令牌信息×

访问掩码也可以看成一张点菜单。VM_READ 是"我要看"，VM_WRITE 是"我要改"，CREATE_THREAD 是"我要在你家墙上开个门"，DUP_HANDLE 是"把你家的钥匙借我配一把"，ALL_ACCESS 是"整本菜单全要"。单点一份可能正常，连点几样就是另一回事。

组合比单项更危险
单项权限都有正常用途，组合起来就是攻击链：

  • PROCESS_VM_READ + PROCESS_VM_WRITE：读写目标内存，凭据窃取、代码替换。
  • PROCESS_VM_OPERATION + PROCESS_VM_WRITE + PROCESS_CREATE_THREAD：经典的远程线程注入三件套。
  • PROCESS_DUP_HANDLE：从高权限进程手里借句柄，绕过"自己申请权限"。
  • THREAD_GET_CONTEXT + THREAD_SET_CONTEXT：线程劫持。

4. EDR 怎么保护 lsass

lsass 存着登录凭据，是凭据窃取的头号目标。典型规则是：任何进程打开 lsass.exe 的句柄，只要申请了 PROCESS_VM_READ 或 PROCESS_VM_WRITE，就在 pre 回调里裁掉。

Mimikatz / procdump
  | OpenProcess(lsass, PROCESS_VM_READ | PROCESS_QUERY_INFORMATION)
  v
ObRegisterCallbacks pre
  | 目标 == lsass.exe -> DesiredAccess &= ~(VM_READ | VM_WRITE)
  v
句柄有效，但没有读内存权限
  | ReadProcessMemory / MiniDumpWriteDump
  v
STATUS_ACCESS_DENIED，或生成 0 字节文件

裁剪之后还剩什么
PROCESS_QUERY_LIMITED_INFORMATION 通常保留，否则任务管理器、资源监视器、备份软件都会出问题。PROCESS_QUERY_INFORMATION 有时也保留，因为它能查的信息有限，但配合其他接口仍可能泄露信息。规则怎么定，取决于厂商对误报和漏报的取舍。

白名单
系统自带的任务管理器创建转储、WER 的故障转储、部分备份软件都会合法访问 lsass。这些进程如果被一刀切，用户会先投诉。EDR 通常按签名、路径、父进程做白名单，白名单本身又成了攻击者的目标——想办法让自己的进程看起来像白名单进程。

PPL 是另一层
lsass 开启 RunAsPPL 后，以受保护进程轻量级（Protected Process Light）运行。普通管理员即使有 SeDebugPrivilege，也打不开它的读内存句柄，这一步发生在对象回调之前。攻击者要绕过它，只能利用签名漏洞驱动或者 PPL 绕过漏洞，这已经属于内核对抗的范畴。

5. 检测维度

对象回调提供的信息可以按五个维度看：

维度看什么异常示例
谁调用者的映像路径、签名、父进程非安全软件访问 lsass
对谁目标进程、目标线程lsass.exe、csrss.exe、winlogon.exe、EDR 自身
要什么DesiredAccessPROCESS_ALL_ACCESS、读写内存同时要
何时时间、频率短时间内反复打开同一目标
结果GrantedAccess、失败次数大量请求被裁剪后继续重试

常见异常模式：

模式含义
单次请求 PROCESS_ALL_ACCESS工具默认行为，高可疑
VM_READ 与 VM_WRITE 同时出现读写内存，转储或注入
CREATE_THREAD + VM_OPERATION + VM_WRITE远程线程注入
对高权限进程请求 DUP_HANDLE借句柄
同一目标短时间多次打开拆分权限、试探规则
拿到句柄后紧接着创建线程或外联组合攻击链

对象回调看不到什么

  • 句柄被使用：ReadProcessMemory、WriteProcessMemory 本身不触发对象回调。
  • 内核直接用对象指针：驱动拿到 PEPROCESS 后可以不创建句柄，直接读写内存。
  • 已经存在的句柄：打开时没被看见，后面再用也不会补一条记录。

所以对象回调通常要和 API Hook、ETW、内核回调、网络事件拼在一起，才能还原完整行为。

6. 规避技术

6.1 权限最小化与拆分

最直接的做法是不要一次要 PROCESS_ALL_ACCESS，而是按需申请：

  • 先用 PROCESS_QUERY_LIMITED_INFORMATION 拿基本信息，这一步通常不触发高危规则。
  • 需要读内存时再单独打开一次，只要 PROCESS_VM_READ。
  • 需要写内存时再单独打开，只要 PROCESS_VM_WRITE。

每次打开都会留下记录，所以这不是隐身，只是把一次高危请求拆成几次低危请求。规则写得粗的 EDR 会漏，规则写得细的 EDR 会因为"同一目标短时间多次打开"而告警。

6.2 借句柄

DuplicateHandle 可以把一个已有句柄复制到另一个进程，同样会触发 OB_OPERATION_HANDLE_DUPLICATE 回调。攻击者的思路是找一个已经持有高权限句柄的可信进程，从它那里复制。

这相当于不自己去配钥匙，而是从已经拿到钥匙的同事那里借一把复制品。复制也要登记，所以它谈不上隐身，只是把"申请"换成了"转借"。

检测点在哪

  • 源进程是谁，它为什么持有这个句柄。
  • 源句柄的权限有多大。
  • 复制到哪个进程，复制后做了什么。

如果源进程是系统组件，而目标进程是个临时目录里的程序，这个组合本身就可疑。借句柄不能隐藏"复制"这个动作，只能隐藏"申请"这个动作。

6.3 不用句柄

驱动可以调用 KeStackAttachProcess 切换到目标进程地址空间，再直接读写内存。整个过程不创建句柄，对象回调完全看不到。

这相当于不配钥匙，直接走通风管道进房间。登记本上一条记录都没有，但怎么进的房间会留下别的痕迹，比如驱动加载和内核内存操作。

代价
需要一个能加载的内核驱动。正常驱动加载会被驱动签名、驱动黑名单、内核回调监控；于是攻击者转向 BYOVD，用带漏洞的合法签名驱动完成读写。对象通知绕过了，但驱动加载成了新的暴露面。

6.4 攻击回调本身

既然回调挡路，就去拆回调：

  • 用漏洞驱动定位并摘除 EDR 注册的回调项。
  • 直接结束 EDR 进程、卸载 EDR 驱动。
  • 阻断 EDR 与控制台的通信，让本地传感器"聋掉"。

这些操作需要内核权限，且要面对 EDR 的自保护（PPL、驱动互相守护、完整性校验）、PatchGuard 和交叉检测。技术门槛高，但一旦成功，后续所有句柄操作都不再受监控。

6.5 对象类型盲区

EDR 通常只给进程和线程对象注册回调。令牌、文件、注册表键这些对象的句柄操作不在覆盖范围内。

令牌窃取就是典型例子：先打开目标进程（只要 PROCESS_QUERY_INFORMATION，风险很低），再 OpenProcessToken、DuplicateTokenEx 拿到令牌。这条路径不碰"进程句柄的高危权限"，也没有令牌对象回调，只能靠 API Hook 或 ETW 发现。

6.6 合法工具

procdump、任务管理器、WER 都能创建进程转储，而且它们是签过名的。攻击者用这些工具访问 lsass，EDR 的"调用者不可信"规则就失效了。

检测只能落到命令行、输出路径、父子关系、目标进程上：一个从临时目录启动的 procdump，把 lsass 转储到用户目录，行为特征和正常运维完全不同。

6.7 抢在注册之前

如果 EDR 驱动不是随系统启动加载，理论上可以在它注册回调之前打开句柄并保留下来，后续一直使用。对 boot-start 的 EDR 无效，对延迟加载的产品有效。这条路径不常见，但说明"对象通知只在注册之后才存在"。

7. 凭据窃取的几条路径

路径是否创建句柄对象回调是否覆盖主要检测
Mimikatz 直接读 lsass是是，权限会被裁剪句柄权限、调用者
procdump 转储是是调用者、命令行、输出路径
任务管理器创建转储是是，常被白名单调用者、目标、频率
SSP 注入 lsass否（对 lsass 不直接开句柄）否注册表、镜像加载
漏洞驱动直接读内存否否驱动加载、漏洞驱动黑名单
PPL 绕过类工具是/部分部分句柄行为、PPL 状态

重点速记

对象通知是配钥匙窗口的登记本，只管配钥匙和转借，不管拿钥匙开门之后干了什么。它能看到谁要什么权限，看不到权限到手后的动作。

  • 注册用 ObRegisterCallbacks，主要覆盖进程和线程对象，pre 改权限，post 看结果，altitude 决定调用顺序。
  • pre 回调只能裁剪 DesiredAccess，不能拒绝创建；权限被裁掉后句柄仍然存在，只是用不了。
  • 保护 lsass 的典型做法是裁掉 PROCESS_VM_READ 和 PROCESS_VM_WRITE，保留查询类权限避免误伤。
  • 绕过路径：少要权限、借句柄、不用句柄（驱动直达）、摘回调、换对象类型。
  • 检测要把调用者、目标、权限、频率、后续行为串起来看，单条句柄记录说明不了太多。
