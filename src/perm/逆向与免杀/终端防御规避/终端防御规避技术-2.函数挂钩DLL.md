EDR 用户态主要靠 Hook `ntdll!Nt*` 拿遥测；绕过核心是“不走被 Hook 的 ntdll”，检测核心是“内存完整性 + 调用栈 + 内核回调”。

---

## 1. 函数挂钩工作原理

 **Hook 的本质**
Hook（钩子）是在程序执行路径上插入拦截点，改变原有控制流。EDR 用 Hook 来“偷看”API 调用参数和上下文；攻击者用 Hook 来劫持或隐藏行为。核心是**控制流重定向**。

### 1.1 Inline Hook
- 修改目标函数开头几条指令，写入 `JMP`，跳到 EDR 的 Handler。
- 原指令被保存到 **Trampoline**，执行完 Handler 后再跳回原逻辑。
- 常见字节：`0xE9`（相对跳转）、`0xFF25`（绝对跳转）。

### 1.2 Trampoline
```text
目标函数:
  JMP EDR_Handler
  原始指令...
Trampoline:
  保存的原始指令
  JMP 目标函数+5
```

**为什么需要 Trampoline**
Trampoline（蹦床）是一段“中转代码”。因为原函数开头被改写了，必须把被覆盖的原始指令保存到另一块内存，执行完 Hook 逻辑后跳回去继续执行，否则原函数就废了。它是 Hook 能“透明”工作的关键。

### 1.3 IAT / EAT Hook
- IAT：改导入地址表，把 API 调用重定向到自己的函数。
- EAT：改导出地址表，影响其他模块调用。
- 比 Inline Hook 更隐蔽，但容易被完整性检查发现。

### 1.4 用户态 vs 内核态
- 用户态：Hook `ntdll.dll`、`kernel32.dll`、`kernelbase.dll`。
- 内核态：注册回调、Minifilter、对象回调，不直接改用户态代码。

**用户态与内核态的分界**
 CPU 分 Ring0（内核）和 Ring3（用户）。用户态程序不能直接操作硬件和内核数据结构，必须通过 `syscall` 指令陷入内核。EDR 在用户态 Hook 成本低、信息全；内核态监控更难绕过，但开发门槛高。


## 2. 用户态到内核执行流程

```text
+------------------+
| 应用程序         |
| CreateFileW      |
+--------+---------+
         |
         v
+------------------+
| kernel32.dll     |
| CreateFileW      |
+--------+---------+
         |
         v
+------------------+
| kernelbase.dll   |
| CreateFileW      |
+--------+---------+
         |
         v
+------------------+
| ntdll.dll        |
| NtCreateFile     |  <-- EDR 用户态 Hook 常在此
+--------+---------+
         | syscall
         v
+------------------+
| 内核             |
| KiSystemCall64   |
+--------+---------+
         |
         v
+------------------+
| 对象管理器/文件系统 |
+------------------+
```

用户态 API 最终都会走到 `ntdll!Nt*`，再通过 `syscall` 进内核。EDR 在 `ntdll` 层 Hook 性价比最高。

**syscall、SSN、Native API**
- **Native API**：`ntdll.dll` 导出的 `Nt*` / `Zw*` 函数，是用户态进入内核的正式门户。
- **SSN（System Service Number）**：每个系统调用在内核系统服务表（SSDT）中的索引号，不同 Windows 版本不同。
- **syscall**：x64 下的 CPU 指令，负责从 Ring3 切到 Ring0，内核根据 `eax` 中的 SSN 分发到对应服务。

因此，绕过 `ntdll` 直接执行 `syscall` 就跳过了用户态 Hook。



## 3. ntdll 常见挂钩函数

| 分类 | 常见函数 | 监控行为 |
|---|---|---|
| 内存 | `NtAllocateVirtualMemory`、`NtProtectVirtualMemory`、`NtWriteVirtualMemory`、`NtReadVirtualMemory`、`NtMapViewOfSection` | 分配、写入、改权限、注入 |
| 进程/线程 | `NtCreateThreadEx`、`NtOpenProcess`、`NtOpenThread`、`NtTerminateProcess`、`NtQueueApcThread` | 远程线程、句柄访问、APC 注入 |
| 模块 | `LdrLoadDll`、`LdrGetProcedureAddress` | DLL 加载、函数解析 |
| 文件/注册表 | `NtCreateFile`、`NtWriteFile`、`NtSetValueKey`、`NtCreateKey` | 持久化、敏感文件访问 |
| 令牌/凭据 | `NtAdjustPrivilegesToken`、`NtOpenProcessToken`、`NtDuplicateObject` | 提权、凭据窃取 |
| 网络 | `WSAConnect`、`WSASocket`、`connect`、`send`、`recv` | C2 通信 |
| 其他 | `EtwEventWrite`、`AmsiScanBuffer` | 致盲 ETW / AMSI |

**为什么 ntdll 是 EDR 的必争之地**
所有用户态敏感操作最终都汇聚到 `ntdll!Nt*`。在这里 Hook 一次，等于监控了所有上层 API（`kernel32`、`kernelbase`、`.NET`、`Win32` 等）的底层调用。对 EDR 是性价比最高的位置；对攻击者，绕过这里就绕过了大部分用户态传感器。

## 4. 用户态 vs 内核态监控

| 维度 | 用户态 | 内核态 |
|---|---|---|
| 位置 | `ntdll.dll` 等 | 内核驱动 |
| 机制 | Inline Hook、IAT Hook | 回调、Minifilter |
| 常见接口 | `Nt*`、`Ldr*` | `PsSetCreateProcessNotifyRoutineEx`、`PsSetCreateThreadNotifyRoutine`、`PsSetLoadImageNotifyRoutine`、`ObRegisterCallbacks`、`CmRegisterCallbackEx` |
| 优点 | 上下文丰富、参数可见 | 更难绕过、底层可见 |
| 绕过难度 | 中 | 高 |
| 典型绕过 | 直接系统调用、Unhooking | BYOVD、移除回调 |

**内核回调是什么**
内核回调是 Windows 提供的一种“事件订阅”机制。驱动注册回调后，当进程创建、线程创建、模块加载、句柄操作等事件发生时，内核会主动通知驱动。它不修改用户态代码，因此用户态 Unhook 对它无效。攻击者要绕过它，通常需要内核权限（如 BYOVD）直接摘除回调。

## 5. 使用 MS Detours 实现挂钩

Detours 是微软的 API Hook 库，核心是事务式 Inline Hook。

### 关键 API
```c
DetourTransactionBegin();
DetourUpdateThread(GetCurrentThread());
DetourAttach(&(PVOID&)pTarget, pDetour);
DetourTransactionCommit();
```

### 逻辑
```text
pTarget:
  JMP pDetour
  ...
Trampoline:
  原始指令
  JMP pTarget+5
```

- `DetourAttach`：把目标函数首部改成跳转。
- Trampoline：保存原始指令，供 Detour 函数调用原逻辑。
- 支持 `DetourDetach` 恢复。
- EDR 和攻击者都可能使用类似技术，区别在目的。

**Detours 的事务机制**
Detours 不是简单改几个字节。它先 `Begin` 进入事务，挂起相关线程（`UpdateThread`），确保修改内存时没有线程正在执行目标函数；然后统一提交（`Commit`）。这样避免多线程下 Hook 到一半导致崩溃。它是线程安全的 Inline Hook 实现。


## 6. 正常执行路径 vs 被 Hook 执行路径

```text
正常:
App -> ntdll!NtX -> syscall -> Kernel

被 Hook:
App -> ntdll!NtX
        |
        | 首字节被改为 JMP -> EDR Handler
        v
   EDR Handler（检查 / 记录 / 阻断）
        |
        +-- 放行 --> Trampoline（原始指令） --> syscall -> Kernel
        |
        +-- 阻断 --> 直接返回错误码
```

重点：  
Hook 后，调用链多了一段 EDR Handler。绕过就是让这段 Handler 不执行，或让 EDR 看不到真实调用。

 **控制流劫持**
程序正常按地址顺序执行。Hook 通过改写指令或函数指针，把执行流“劫持”到第三方代码。EDR 的 Handler 可以检查参数、记录栈、决定放行或拒绝。攻击者的绕过，本质是让控制流不经过这个第三方代码，或者让第三方代码看不到真实意图。

## 7. 注入 DLL

### 目的
- EDR：把 Agent 注入目标进程，安装用户态 Hook。
- 攻击者：注入 Unhook 模块、直接系统调用模块、窃取数据。

### 常见方式
- `CreateRemoteThread` + `LoadLibrary`
- `QueueUserAPC`
- `SetWindowsHookEx`
- 手动映射（Manual Mapping）
- 进程镂空（Process Hollowing）

### 检测点
- 远程线程创建
- 非签名模块加载
- 私有内存中的 PE
- 异常 `LoadImage` 回调
- 模块路径与磁盘不一致

 **DLL 注入为什么能监控**
DLL 注入是把一个动态库强制加载到目标进程地址空间。一旦加载，它的代码就在目标进程内运行，可以调用 `DetourAttach` 挂钩该进程的 `ntdll`，从而监控该进程的所有 API 调用。EDR 用这招把传感器部署到每个受保护进程；攻击者用这招把绕过模块送进去。

## 8. 检测函数挂钩

| 方法 | 说明 |
|---|---|
| 内存字节比对 | 对比 `ntdll .text` 与磁盘/干净副本，查 `0xE9`、`0xFF25` |
| 调用栈分析 | `syscall` 返回地址不在 `ntdll` 预期范围 |
| 模块完整性 | PE 节区哈希、校验和 |
| 硬件断点 | 检查调试寄存器 DR0-DR3 |
| 内存扫描 | 查私有可执行内存、非映像节 |
| 内核回调交叉验证 | 用户态没看到，但内核回调看到，说明被绕过 |

 **完整性校验与调用栈分析**
 - **完整性校验**：正常 `ntdll` 的代码段应与磁盘文件一致。如果开头出现 `JMP`，或哈希对不上，说明被 Hook。
 - **调用栈分析**：合法 `syscall` 的返回地址应落在 `ntdll` 的存根范围内。若返回地址在私有内存或未知模块，说明可能是直接系统调用或劫持。
 两者结合，能发现大多数用户态绕过。



## 9. 规避函数挂钩

### 9.1 直接系统调用
- 自己执行 `syscall`，不经过 `ntdll!Nt*`。
- 伪代码：
```asm
mov r10, rcx
mov eax, SSN
syscall
ret
```
- 优点：绕过用户态 Hook。
- 缺点：调用栈异常，SSN 依赖系统版本。

 **直接系统调用的本质**
 直接系统调用就是“跳过前台，直接找内核”。它不调用 `ntdll` 里被 Hook 的存根，而是自己准备寄存器（`r10`、`eax` 等）并执行 `syscall` 指令。由于没有经过 `ntdll`，EDR 的 Inline Hook 完全看不到。但 CPU 进入内核后，调用栈的返回地址会暴露它不是从 `ntdll` 来的，因此可能被栈检测发现。

### 9.2 动态解析系统调用编号
- 从 `ntdll` 存根动态读取 SSN。
- 常见技术：Hell's Gate、Halo's Gate、Tartarus Gate。
- 解决不同 Windows 版本 SSN 不同的问题。
- 若存根被 Hook，可从邻近函数推算，或从磁盘干净 `ntdll` 解析。

 **SSN 动态解析**
 SSN 是系统调用号，硬编码在不同 Windows 版本会错。动态解析就是在运行时从 `ntdll` 的 `Nt*` 存根中读取 `mov eax, SSN` 指令，提取出正确的编号。如果该存根被 Hook，就查看相邻存根，利用系统调用号连续的特性推算（Hell's Gate / Halo's Gate）。这样直接系统调用就能跨版本工作。

### 9.3 重新映射 ntdll.dll
- 从磁盘或 `KnownDlls` 获取干净 `ntdll.dll`。
- 映射为新节，复制 `.text` 覆盖被 Hook 区域。
- 目的：恢复原始函数字节，使 Hook 失效。
- 检测点：
  - 内存与磁盘不一致
  - 私有内存中的 `ntdll`
  - 非映像节
  - 模块重载行为

 **重新映射 ntdll 的原理**
 EDR 挂钩的是内存中的 `ntdll` 代码段。攻击者从磁盘重新加载一份干净的 `ntdll.dll`，把它映射到当前进程，然后用干净副本的 `.text` 覆盖已被 Hook 的内存区域。这样函数开头恢复原样，Hook 失效。检测点在于：正常进程的 `ntdll` 应与磁盘一致，若出现私有映射或节区异常，就可疑。

### 9.4 其他
- 间接系统调用：跳到 `ntdll` 中未 Hook 的 `syscall` 指令，保持调用栈可信。
- IAT 重定向。
- 硬件断点劫持。
- ETW / AMSI 修补致盲。

## 10. 重点速记

 **攻防的核心矛盾**
 EDR 要在调用链上插入监控点；攻击者要移除或绕过监控点。用户态焦点是 `ntdll` 的完整性与调用栈可信度；内核态焦点是回调是否被摘除。谁控制调用链，谁就掌握可见性。

- EDR 用户态 Hook 核心：`ntdll!Nt*`。
- 绕过三件套：直接系统调用、动态 SSN、重新映射 `ntdll`。
- 检测三件套：内存完整性、调用栈、内核回调。
- 攻防焦点：调用链是否可信、SSN 是否动态、`ntdll` 是否干净。
- 用户态绕过容易被调用栈检测；内核态绕过难度更高，但收益更大。

当今终端安全领域，大多数成熟的EDR将函数挂钩作为辅助遥测手段，而更主要依赖更加稳定可靠的监控传感器来有效监控威胁。
