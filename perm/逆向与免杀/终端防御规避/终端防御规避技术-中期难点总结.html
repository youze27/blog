终端防御规避技术-中期难点总结

卷卷原创2026/11/1大约 13 分钟应急响应应急响应EDR终端防御与规避免杀内核回调Minifilter

前面几章按传感器一个个讲：进程线程通知、对象回调、镜像加载、注册表、微筛选器。这一篇换个角度，把这些监控点放在一起比：哪些需要微软的反恶意软件资质才能注册，哪些普通签名驱动就能挂，攻击者在每条线上的对抗入口分别在哪。

一、MVI、ELAM 与 PPL-AM：高危回调的入场券

三个名词

  • MVI（Microsoft Virus Initiative）：微软的反恶意软件厂商合作计划，是厂商身份的准入。
  • ELAM（Early Launch Anti-Malware）：早期启动反恶意软件驱动，在系统启动早期加载，需要微软专门的 ELAM 签名。
  • PPL-AM（Protected Process Light，Anti-Malware 级）：反恶意软件级别的受保护进程，普通管理员拿到 SYSTEM 令牌也打不开它。

三者绑在一起：MVI 会员 + 自有 ELAM 驱动 + 微软特殊 ELAM 签名，才能拿到 AM 特权。不是随便一个 EDR 都有这个资格，很多国内 EDR 用的是普通 WHQL 驱动。

资质和回调的关系

ObRegisterCallbacks、PsSetCreateProcessNotifyRoutineEx、PsSetLoadImageNotifyRoutineEx 这类高危回调，需要 AM 特权才能注册。普通 WHQL 签名的驱动注册不了 OB 回调，只能走 FltMgr 微筛选器、普通 Cm 回调、ETW 这几条路。

国内拿到这套资质的厂商

  • 火绒：MVI 成员，有自研 ELAM 驱动，Blackhat 公开的 ELAM 列表里收录了 Beijing Huorong Network Technology Co., Ltd.。个人版和企业版都支持 PPL-AM，用 Ob 回调保护 LSASS、拦截 OpenProcess。
  • 瑞星：老牌厂商，很早就进 MVI，ELAM 驱动在公开样本清单里有记录，瑞星杀毒和瑞星 EDR 具备这套能力。
  • 安恒信息：官方宣布加入 MVI，明御 EDR 支持这条 Windows 原生反恶意软件特权链路。
  • 360：很早就有 ELAM、PPL、OB 回调，红队对抗里最常遇到。早期内核对抗资料大量提到 360 用 Ob 回调保护进程、拦截 LSASS 打开，个人版和企业终端产品都有这套机制。

没走这条路的厂商

奇安信、深信服、启明星辰、天融信、安天的 EDR 同样有大量内核监控：钩子、minifilter 文件过滤、注册表回调。但一部分版本没有走 MVI + ELAM + PPL-AM 这条官方特权通道，注册不了 ObRegisterCallbacks 和 Ps 系列高危版本，方案是自己做 Inline Hook，或者换别的监控点。这和微软官方给反恶意软件预留的插槽不是一回事，对抗思路也不一样。

两个容易踩的坑

  • MVI 是厂商身份准入，不等于它所有产品都启用 ELAM。 火绒个人版默认是 PPL-AM，但有些政企定制版本可以关掉 PPL，关掉之后就不能注册 OB 回调了。
  • 有 MVI 不等于产品里一定开 OB 回调。 厂商拿到资格后，可以出于兼容性、蓝屏风险的考虑不用 OB 回调，改用别的监控方案。

红队实战里的区分

火绒、瑞星、360、安恒是正规 PPL-AM + OB 回调，摘除 OB 回调（EDRSandBlast 这类工具）是经典对抗路线。没有 AM 特权的国产 EDR，拦截不在 OB 回调这一层，摘 OB 回调对它无效，要找它自己的 Inline Hook 和 minifilter。

二、镜像加载通知 PsSetLoadImageNotifyRoutine

镜像是什么

镜像是可以被映射加载进内存的 PE 文件：EXE、DLL、SYS 驱动。这个回调在镜像被映射进进程内存时触发。注意是映射（载入内存），不是文件打开。

典型场景有三个：LoadLibrary 加载 DLL、驱动加载（SYS 镜像）、新进程启动时主 EXE 被映射进内存。它属于 Ps 系列通知回调，是微软官方预留的插槽，和 Ob 回调是两套东西。

和进程、线程通知的分工

回调通知时机
PsSetCreateProcessNotifyRoutineEx进程创建诞生时
PsSetCreateThreadNotifyRoutine线程创建时
PsSetLoadImageNotifyRoutineDLL/EXE/SYS 被映射进内存那一刻

EDR 拿它做什么

  • 记录日志：哪个进程加载了哪个 DLL，路径、签名、哈希。
  • 告警拦截：盯高危 DLL，比如无签名 DLL、注入常用载荷、mimikatz 相关模块。
  • 跟踪注入：远程线程注入、APC 注入，只要 DLL 被映射，正常情况下就会触发这个通知。

权限门槛

Win10 1709 之后，增强版 PsSetLoadImageNotifyRoutineEx 同样需要 PPL-AM 身份，走 MVI + ELAM 那一套；没有 AM 特权的普通驱动调 Ex 版本会失败。老版本 PsSetLoadImageNotifyRoutine 限制宽松一些，但现在主流 EDR 都用 Ex 版本。

逃逸要点

  • 反射注入（Reflective DLL Injection）：自己手动解析 PE、自己分配内存、自己修复导入表，绕开系统原生 LoadLibrary 路径，不调用系统的镜像映射 API，就不触发通知。
  • 摘除回调链表：思路和摘 Ob 回调一样，但有 PPL 保护，摘除难度高。
  • 它只管镜像映射，监控不到直接写内存。

高频误区：shellcode 不触发

  • DLL 是 PE 镜像，√ 触发镜像加载通知。
  • 裸 shellcode 不是 PE 镜像，× 不触发。

另一个常混的点：镜像加载通知不是文件监控。DLL 还在硬盘上、没有映射进进程内存，它不触发；反过来文件监控（FltMgr）是只要你打开、读取这个 DLL 文件就触发。

三、注册表通知 CmRegisterCallbackEx

Cm 是什么

Cm 是 Configuration Manager，配置管理器，Windows 注册表的内核管理者。这个回调是微软给注册表操作预留的官方插槽：驱动注册之后，任何进程对注册表项的增、删、改、打开、查询，都会先触发回调。逻辑和 Ob 回调很像，系统在注册表管理器的流程里预埋了分支，注册了回调就调用，没注册直接走原生流程。

EDR 拿它监控什么

注册表是恶意程序持久化最喜欢的地方：Run、RunOnce 开机自启项，服务注册表项（创建恶意服务），驱动服务、WMI 持久化、AppInit_DLLs、Image File Execution Options（IFEO 劫持），还有篡改安全设置、关闭 Defender 的注册表键。EDR 在这里拦截写入、记录行为、阻止持久化。

权限门槛最低

Cm 回调不需要 MVI、不需要 ELAM、不需要 PPL-AM 身份，普通 WHQL 签名的驱动直接就能注册。很多没有 MVI 资质的厂商，注册不了 OB 回调和 PsLoadImageEx，但全都可以挂 Cm 注册表回调。

Pre 和 Post 两个阶段

  • Pre（操作之前）：可以直接拒绝本次注册表写入，拦截持久化。
  • Post（操作完成之后）：只做日志上报。

逃逸思路

  • 摘除 Cm 回调链表节点，内核对抗手段。
  • 利用冷门的、EDR 没关注到的注册表路径做持久化，EDR 一般只重点监控 Run、服务这类高频键。
  • 通过间接 API 或内核路径操作注册表，绕过用户态回调的监控范围，部分 Cm 回调只监控特定注册表根键。

四、KAPC：内核异步过程调用

APC 是什么

APC 全称 Asynchronous Procedure Call，异步过程调用。可以把它理解成塞给某个线程的待执行任务小纸条：放进这个线程专属的 APC 队列，等线程下一次被调度、IRQL 降到合适级别时，系统自动执行纸条上的函数，执行时用的是这个线程的上下文、这个进程的地址空间。

KAPC 和用户 APC 的分水岭

KAPC 就是 _KAPC，内核 APC 对应的内核结构体。用户态的 QueueUserAPC 必须等线程进入可警报等待（alertable）才会执行；内核 APC 不需要线程进入可警报等待，只要线程被调度、IRQL 降到 APC_LEVEL 或 PASSIVE_LEVEL，队列里的 KAPC 就会被消费。这是红队和 EDR 都重视它的根本原因。

每个线程的 KTHREAD 结构里自带 APC 队列，由 KAPC_STATE 管理。

系统原生用途

  • 异步 IO 完成通知，比如 ReadFileEx 的完成回调。
  • 文件系统、minifilter 微筛选器的回调任务。
  • 线程挂起、恢复、上下文操作。

两种内核 APC

类型运行级别特点
普通内核 APC（Normal Kernel APC）PASSIVE_LEVEL能抢占用户代码和用户 APC，文件过滤驱动大量使用
特殊内核 APC（Special Kernel APC）APC_LEVEL优先级更高，连普通内核 APC 都能抢占，I/O 完成和紧急任务用它

防守方用法：EDR 的 APC 注入

EDR 的驱动拿到进程创建通知后，构造一个 KAPC 排队到刚创建的新进程主线程。线程一跑起来，KAPC 里的内核例程负责在用户态把 EDR 的监控 DLL 拉起来，把钩子和监控逻辑注入进目标进程。也就是在恶意代码执行之前，先把 EDR 的钩子扎进去。

攻击方用法：Early Bird APC 注入

在进程刚创建、主线程还处于挂起状态时构造 KAPC 排队进去；目标线程恢复运行、系统处理 APC 队列，攻击者放的 shellcode 就被自动执行。

好处有三个：复用目标线程上下文，不新建线程，不触发"新建远程线程"这类告警；不需要 CreateRemoteThread，避开 OB 回调对 OpenThread、远程线程的检查；抢在 EDR 自己的 KAPC 注入、EDR DLL 加载之前执行。

边界

KAPC 是执行载体机制，不属于 Ob 回调、PsNotify 或 Cm 回调，是一套独立的线程调度机制。另外，排队 KAPC 这件事本身现在会被很多 EDR 监控，APC 入队和 APC 执行有专门的行为检测。

类型运行层级是否需要 alertable 等待调用方
用户 APCR3√用户态 QueueUserAPC
内核 APC（普通/特殊）R0×内核驱动，KeInitializeApc + KeInsertQueueApc

五、微筛选器 Minifilter 与 FltMgr

定位

FltMgr 是 Filter Manager，过滤管理器，Windows 内置的内核框架（fltmgr.sys）；微筛选器就是跑在这个框架上的驱动，专门给文件和卷操作的监控、拦截设计。它和其他几套体系的分工：Ob 回调管句柄打开，Cm 回调管注册表，PsNotify 管进程、线程、镜像加载，Minifilter 管文件系统上的打开、读、写、删除、重命名、创建、属性修改。

为什么要有 FltMgr

早年是旧的 Sfilter 过滤驱动模型，链式挂载：A 过滤驱动挂上去，B 再挂在 A 上面。问题很致命：顺序写死，容易死锁、蓝屏；一个过滤驱动崩了，整条链全挂，文件系统直接出问题；各家的杀毒、EDR、备份软件过滤驱动互相打架。

微软后来做了 FltMgr 当调度中间层，第三方安全、备份、加密软件都写成 minifilter 注册进来，不再直接挂载文件驱动，由 FltMgr 统一调度管理。

核心原理：Altitude 海拔

每个微筛选器注册时必须带一个数字：Altitude（海拔值）。数字越大，位置越靠近应用层，越先看到请求；数字越小，越靠近文件系统底层。

I/O 往下走（打开文件、写文件）时，先跑海拔大的，再跑海拔小的，这是 Pre 阶段；操作完成、结果往回传时顺序反过来，先跑海拔小的，这是 Post 阶段。

和旧链式模型最大的区别就在这里：顺序不由谁先加载决定，而由 Altitude 决定。号段由微软官方分配，厂商要向微软申请，杀毒和勒索防护的区间是 320000–329999，正规厂商不会随便填一个数字。

PreOperation 和 PostOperation

和 Ob 回调的 Pre/Post 思路类似，但处理的是文件 IRP。

  • PreOp（前置回调，I/O 下发之前）：请求刚下来，还没交给文件系统执行。这里能直接拦截本次操作：拒绝打开、拒绝写入、阻止删除，勒索防护的核心就在 PreOp；也可以检查路径、文件名、进程和要写入的内容。真正的拦截能力全部放在 PreOp。
  • PostOp（后置回调，操作完成之后）：文件读写已经做完了，只能做日志记录、统计、上报，拦不住。
  • 微筛选器也可以选择旁路某个 I/O，直接交给下一个筛选器，自己不处理。

监控哪些动作

几乎所有文件相关的 IRP：ZwCreateFile 创建打开、读、写、删除、重命名、移动、修改属性和权限、创建目录、流操作和备用数据流（ADS）、卷挂载卸载。

高频误区：文件 I/O 不等于镜像映射

  • 程序调 CreateFile 打开读取一个 DLL：触发 Minifilter，不触发镜像加载通知。
  • 程序 LoadLibrary 把 DLL 映射进内存：触发镜像加载通知，同时也经过 Minifilter 的读 I/O。
  • 反射注入直接从内存解开 PE，不走文件读取、不走 LoadLibrary：两个都能绕过。

还有一点和前面串起来：File 对象虽然有句柄，但不能用 Ob 回调监控文件打开，文件监控这件事就是交给 Minifilter 的。

权限门槛

写 minifilter 不需要 MVI、不需要 ELAM、不需要 PPL-AM，驱动拿到正常 WHQL 签名就能向 FltMgr 注册。所以没有 MVI 资质的 EDR 做不了 OB 回调、用不了 PsLoadImageEx，照样能做勒索防护，靠的就是 Minifilter。这也是国内 EDR 最普遍的一条防线。

攻防视角

防守侧最经典的场景是勒索防护：监控 docx、xlsx、pdf 这些文档的批量修改和加密写入，发现进程大量改写文档，PreOp 直接拦截写操作，阻断勒索加密。

攻击侧的思路：

  • 找 Altitude 顺序缺陷，或者 EDR 筛选器自身的逻辑漏洞。
  • 用特殊路径、设备路径、符号链接、ADS、卷设备名，绕过只监控普通 Win32 路径的规则。
  • 内核层摘除微筛选器节点，节点挂在 FltMgr 的全局列表上，手法类似摘 Ob 回调；但主流 EDR 会保护自己的筛选器对象，有 PPL 和对象保护，难度高。
  • 载荷全程内存运行，不落地写文件。只要不碰磁盘文件，微筛选器对你无效。

六、四类监控体系对照

体系管理者回调 API管控对象需要 MVI/PPL-AM

OB 回调和 Ps 通知挂在反恶意软件特权插槽上，注册表回调和微筛选器门槛低，普通签名驱动就能挂。判断一个 EDR 的监控挂在哪一层，决定了摘回调这条路走得通走不通。
