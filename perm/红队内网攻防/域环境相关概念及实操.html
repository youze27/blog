域环境相关概念及实操

卷卷原创2024/11/11大约 9 分钟渗透测试域渗透ActiveDirectoryKerberos

域相关概念

企业里服务器、个人 PC、笔记本越来越多，如果逐台维护，成本高、安全策略也难以统一。域环境可以把这些计算机纳入统一管理，主要好处有：

  1. 权限集中管理，降低运维成本；
  2. 统一下发并执行安全策略，权限划分更清晰；
  3. 域控可以把域成员桌面上的文件同步到服务器，便于备份；
  4. 用户只需登录一次域账号，就能访问被授权的所有资源，不必反复认证。

活动目录（Active Directory）

Active Directory（AD，活动目录）是 Windows Server 中的目录服务，用于集中管理用户、计算机和其他网络资源，保证网络的高可用性、安全性和一致性。

主要功能：

  1. 账号集中管理：用户、计算机等账号统一存储在服务器上；
  2. 身份验证与授权：验证用户凭据，并决定其能否访问文件或应用；
  3. 软件集中管理：统一下发软件、安装网络打印机；
  4. 环境集中管理：统一客户端桌面、IE、TCP/IP 等设置；
  5. 增强安全性：统一部署杀毒软件、集中管理权限、统一密码策略。

架构与组件

  • 域控制器（Domain Controller）：保存活动目录信息副本，并负责把变更复制到其他域控，保持数据同步；
  • 架构目录分区（Schema Directory Partition）：存储林中所有对象和属性的定义，以及创建新对象的规则；
  • 配置目录分区（Configuration Directory Partition）：存储 AD DS 的结构，例如有哪些域、哪些站点。

逻辑结构

域（Domain）

域是 AD 的基本单位，是一组共享同一目录数据库的对象。域提供安全边界，通过域控制器存储和复制目录信息，处理身份验证请求。

组织单位（Organizational Unit，OU）

OU 是域内的容器，用于组织和管理对象，可以嵌套形成层次结构。管理员可以用 OU 表示部门、团队，并通过委派权限分配管理任务。

树（Tree）

一组共享同一命名空间的域组成一棵树。树中的第一个域是根域，其余是子域，域之间通过双向可传递的信任关系连接。

森林（Forest）

一组共享相同架构、配置和全局编录的树组成森林。森林中的树可以有不同的命名空间，但通过信任关系连接。森林是 AD 的最高层次结构。

域控制器（Domain Controller，DC）

域控制器本质上是运行 Active Directory 服务的服务器：

  • 存储 AD 数据库，包括用户、计算机、组、策略等对象；
  • 处理用户登录和身份验证请求；
  • 把目录数据复制到其他域控，保证一致性和容错；
  • 提供 DNS 服务，解析网络中的域名。

域用户（Domain Users）

域用户是 AD 中定义的用户账户，用于身份验证和访问控制：

  • 使用用户名和密码登录网络；
  • 访问被授权的网络资源和应用；
  • 接受组策略的管理和配置。

域计算机（Domain Computers）

域计算机是加入 AD 域的计算机，可以是工作站、服务器或其他设备：

  • 使用域用户账户登录和认证；
  • 访问域中的资源和应用；
  • 接受域控的管理和配置，例如软件分发、安全更新。

组（Groups）

组是 AD 中用于管理用户和其他对象的容器：

  • 为组分配权限，简化权限管理；
  • 支持嵌套组，一个组可以包含其他组；
  • 便于批量添加、删除或移动用户。

策略（Policies）

策略定义和管理网络行为与安全性：

  • 组策略：管理用户和工作站的配置，如桌面、软件安装、安全设置；
  • 站点策略：定义站点内的复制关系和拓扑；
  • 密码策略：定义密码复杂性、长度、有效期等要求。

NTLM 认证流程（NTLMv2）

NTLM 认证在工作组和域环境中的流程不同。Windows 使用 NTLM 算法在本地保存密码 Hash，Hash 保存在 SAM 文件中；域用户的 Hash 则保存在域控的 NTDS.dit 中。

SAM 文件：C:\Windows\System32\config\SAM
NTDS.dit：C:\Windows\NTDS\NTDS.dit

NTLM（New Technology LAN Manager）是一套 Windows 安全协议，用于提供包含完整性和机密性的身份验证。常见版本有 NTLMv1、NTLMv2 和 NTLMv2 Session，其中 NTLMv2 最常用。

NTLM 使用质询-响应机制：服务器发送质询，客户端计算响应来证明身份，同时协议还提供数据完整性和加密功能。

在工作组中

① 发送协商请求（Negotiate）

客户端访问受限服务时输入用户名和密码，把密码转换为 NTLM Hash 并缓存。随后发送协商请求包，其中包含用户名、域名以及申请认证的服务信息，记为 TYPE 1。

② 发送质询请求（Challenge）

服务端收到 TYPE 1 后，如果用户名存在，就生成一个 16 字节的随机值 Challenge（NTLMv1 为 8 字节），连同支持的服务信息组成质询请求包，记为 TYPE 2。

③ 发送认证响应（Authenticate）

客户端使用 HMAC-MD5 算法对 TYPE 2 中的 Challenge 做消息摘要，得到 NTLMv2 Response，再结合用户名、Challenge 等信息生成 TYPE 3。具体来说，客户端把缓存的 NTLM Hash 和 Challenge 作为 HMAC-MD5 的输入，得到摘要值。

④ 服务端验证并应答（Reply）

服务端收到 TYPE 3 后，根据用户名取出本地缓存的 NTLM Hash 和 Challenge，同样计算 HMAC-MD5，与 TYPE 3 中的 NTLMv2 Response 比较。相同则认证成功，否则拒绝访问。

在域环境中

域环境下，所有域用户的 Hash 都存在域控的 NTDS.dit 中，服务器无法像工作组那样在本地完成第 ④ 步，只能作为中间人把验证请求转发给域控。

前三个步骤与工作组基本一致，域中新增以下步骤：

④ 验证转发：服务器把 TYPE 3 转发给域控制器，请求验证。

⑤ 验证回复：域控用与工作组第 ④ 步相同的方法验证请求，并把结果返回给服务器。

⑥ 回复转达：服务器把验证结果转达给客户端。

Kerberos 认证流程

Kerberos 是域环境中常用的网络身份验证协议，基于票据（Ticket）工作。整个流程涉及三方：客户端、服务端和 KDC（Key Distribution Center）。在 Windows 域中，域控承担 KDC 的角色。

针对 Kerberos 的攻击包括黄金票据、白银票据、各种中继攻击、委派滥用和协议漏洞等。

简写说明
KDC密钥分发中心，负责票据生成和管理，包含 AS 和 TGS
AS认证服务，为客户端生成 TGT
TGS票据授予服务，为客户端生成访问特定服务的票据
TGT票据授予票据，由 AS 生成，用于获取服务票据
ST服务票据，由 TGS 生成，允许访问特定服务

Kerberos 的工作流程至少需要三个实体参与：客户端、服务器和 KDC，其中 KDC 包含 AS 和 TGS。

① 向认证服务器 AS 请求

客户端向 AS 发送包含密文的请求包，除密文外还包括能体现用户身份的主体名等信息。

密文由客户端使用密钥对 ClientID、随机 Challenge、时间戳等数据加密得到，通常使用对称加密算法（如 AES）。密钥一般由客户端密码的 Hash 经过密钥派生函数生成。

② 认证服务器 AS 响应

AS 根据请求中的用户名，在本地找到该用户的密码 Hash，用相同的密钥派生方法得到密钥，然后解密密文。解密成功说明客户端拥有正确密码。

随后 AS 在响应中放入票据授权凭证 TGT，TGT 中包含用户特权证书 PAC（Privilege Attribute Certificate），PAC 指明了用户权限。

TGT 使用 krbtgt 账户的 NTLM Hash 对客户端身份等信息做对称加密得到。krbtgt 是 KDC 中的特殊账户，用于生成和分发 TGT。

③ 向票据授权服务器 TGS 请求

客户端携带密文 TGT，向 TGS 请求访问目标应用服务的票据。

Windows 10 入域

  1. 在服务器端配置静态 IP，并把 DNS 指向域控。

  2. 修改计算机全名，方便识别。

  3. 安装 AD 域服务角色。

  4. 安装完成后把服务器升级为域控制器。

  5. 安装过程中如果没有密码，需要设置强密码。

  6. 完成后服务器即成为域控。

  7. 在 Windows 10 上配置 IP 和 DNS，准备加入域。

  8. 输入域管理员账号密码，加入域。

  9. 加入后重启计算机。

  10. 在域控上可以看到该计算机已经加入。

  11. 把域用户加入某个部门。

  12. 设置域用户密码及相关策略。

  13. 查看域用户的登录方式。

  14. 使用域用户名登录。

Windows 7 入域

  1. Windows 7 使用相同的方法创建并加入域。

  2. 用户也可以在域控制器上直接添加。

域相关命令

查看当前域信息：

net view /domain

查看所有域。

net user /domain

查看域用户。

net group /domain

查看域中的组。

net group "domain admins" /domain

查看域管理员账户。

net group "domain controllers" /domain

查看域控制器。

net group "domain computers" /domain

查看加入域的所有普通计算机。

dsquery server

查询活动目录中的域控制器。

dsquery user

查询活动目录中的所有用户。

net config workstation

查询当前计算机属于哪个域。

net time /domain

查看主域服务器的时间。

ipconfig /all

查看网络配置。

添加普通域用户并把其提升为域管理员：

net user xiaomi passwd /add /domain
net group "Domain Admins" xiaomi /add /domain
