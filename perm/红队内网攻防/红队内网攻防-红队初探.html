红队内网攻防（一）：红队初探与基础设施建设

第1章 红队初探

红队不是"更猛的渗透测试"。它强调的是在授权范围内，以贴近真实攻击者的方式，围绕明确的业务目标，验证防御体系到底能不能发现、能不能阻断、能不能响应。这一章先把概念、方法论和参考模型理清楚，后面所有技术动作才有落脚点。

1.1 攻防演习概述

攻防演习（也常被称为"护网""HW""红蓝对抗"）是一种以实战化为目标的网络安全检验活动。组织方预先设定靶标与规则，红队负责攻击，蓝队负责防守，最终以双方的实际表现评估安全能力。

一次完整的攻防演习通常包含以下要素：

要素说明
组织方行业主管单位、企业自身或第三方机构，负责制定规则与靶标
红队（攻击方）在授权范围内对目标发起攻击，目标是获取指定权限或数据
蓝队（防守方）负责监测、阻断、溯源与应急处置
靶标明确要保护的核心业务系统或数据，是评分的关键
规则授权范围、时间窗口、禁止动作（如拒绝服务、破坏数据）
评分依据拿到靶标的数量、隐蔽性、被发现的次数等综合计分

攻防演习的价值不在于"谁赢了"，而在于暴露真实短板：

  • 检验现有安全设备（WAF、IDS/IPS、EDR、态势感知）的实际检出能力；
  • 检验安全运营团队（SOC）的监测与响应速度；
  • 验证纵深防御是否成立，单点失陷后能否快速遏制；
  • 推动资产梳理、漏洞治理、权限收敛等基础工作。

重要前提：所有攻击行为必须事先获得书面授权，并严格限定在约定范围内。超出授权范围的测试属于违法行为。

1.2 渗透测试和红队评估

1.2.1 渗透测试

渗透测试（Penetration Testing）是以发现和验证技术漏洞为核心的安全评估方式。它通常有明确的范围（如某几个 IP、某套 Web 系统），在较短时间内尽可能多地找出漏洞，并给出修复建议。

典型流程：

  1. 信息收集：域名、IP、端口、指纹、公开信息；
  2. 漏洞发现：手工测试 + 自动化扫描；
  3. 漏洞利用：验证漏洞是否真实可利用；
  4. 影响评估：说明漏洞可能造成的危害；
  5. 报告输出：漏洞清单、复现步骤、修复建议。

渗透测试的特点是"广度优先、以漏洞为中心"——目标是尽可能把问题找全，过程是否隐蔽通常不是重点。

1.2.2 红队评估

红队评估（Red Team Assessment）以业务目标为导向。它不追求漏洞数量，而是模拟真实攻击者，回答一个更本质的问题：

以真实攻击者的能力和耐心，能否达成某个具体的业务目标（例如拿到核心数据库、控制域控、窃取指定数据）？

红队评估的典型特征：

  • 目标驱动：围绕"拿到什么"设计攻击路径，而不是"能打穿什么就打什么"；
  • 强调隐蔽：尽量模拟 APT，避免被蓝队发现，甚至要评估"被发现需要多久"；
  • 周期更长：可能持续数周甚至数月，包含长期驻留与多次尝试；
  • 手段更全：除技术漏洞外，还包括社会工程、钓鱼、物理入侵、供应链等；
  • 关注防守视角：不仅看能否打进去，还看蓝队的检测、响应与处置能力。

1.2.3 渗透测试和红队评估的区别与联系

维度渗透测试红队评估
核心目标发现并验证漏洞达成特定业务目标
范围明确、相对固定更宽泛，可能包含人、供应链、物理
隐蔽性一般不作要求高度强调，尽量不被发现
周期数天到数周数周到数月
手段以技术漏洞为主技术 + 社工 + 钓鱼 + 物理等
产出漏洞清单与修复建议攻击路径、防守能力评估与改进建议
评价标准漏洞数量与危害目标达成度与被发现情况

两者并非对立：渗透测试是红队评估的技术基础，红队评估是在渗透测试能力之上的整体对抗演练。实际项目中，往往先用渗透测试摸清技术面，再以红队视角串联成完整攻击链。

1.3 常见的攻击模型

攻击模型是对攻击过程的抽象，用来指导测试、编排战术和评估防守。最常用的有三个：PTES、MITRE ATT&CK 和网络杀伤链。

1.3.1 PTES 模型

PTES（Penetration Testing Execution Standard，渗透测试执行标准）把渗透测试划分为七个阶段：

  1. 前期交互（Pre-engagement Interactions）：确定范围、授权、目标与规则；
  2. 情报收集（Intelligence Gathering）：被动与主动信息收集；
  3. 威胁建模（Threat Modeling）：识别高价值目标与可行攻击面；
  4. 漏洞分析（Vulnerability Analysis）：发现并验证漏洞；
  5. 漏洞利用（Exploitation）：获取初始访问权限；
  6. 后渗透（Post Exploitation）：提权、横向、持久化、数据获取；
  7. 报告（Reporting）：输出结论、证据与修复建议。

PTES 强调流程规范，适合作为渗透测试项目的执行框架。

1.3.2 MITRE ATT&CK 模型

ATT&CK（Adversarial Tactics, Techniques, and Common Knowledge）是由 MITRE 维护的攻击者行为知识库。它以矩阵形式组织：

  • 战术（Tactic）：攻击者"为什么"要做，即阶段性目标；
  • 技术（Technique）：攻击者"怎么做"；
  • 子技术（Sub-technique）：更细粒度的实现方式。

企业版矩阵常见的 14 个战术（按攻击进程排列）：

侦察 → 资源开发 → 初始访问 → 执行 → 持久化 → 权限提升 → 防御规避 → 凭据访问 → 发现 → 横向移动 → 收集 → 命令与控制 → 数据渗出 → 影响

ATT&CK 的实际用法：

  • 红队：用技术编号（如 T1059、T1003）规划并记录攻击动作；
  • 蓝队：把检测规则、日志源与具体技术对齐，找出覆盖盲区；
  • 双方共用一套语言，便于量化"检测覆盖率"。

1.3.3 网络杀伤链

网络杀伤链（Cyber Kill Chain）源自军事领域，把一次入侵拆成七个环节：

  1. 侦察（Reconnaissance）：收集目标信息；
  2. 武器化（Weaponization）：制作恶意载荷；
  3. 投递（Delivery）：通过邮件、Web、U 盘等投递；
  4. 利用（Exploitation）：触发漏洞执行代码；
  5. 安装（Installation）：植入后门、建立持久化；
  6. 命令与控制（Command & Control）：与 C2 服务器通信；
  7. 目标行动（Actions on Objectives）：窃取数据、横向移动、破坏。

杀伤链的最大价值在于防守方"在任意一环打断即可阻断攻击"，因此常被用来设计分层检测策略。

1.4 安全风险参考列表

1.4.1 OWASP TOP 10

OWASP Top 10 是最广为人知的 Web 应用安全风险列表（当前主流版本为 2021 版）：

编号风险简述
A01访问控制失效（Broken Access Control）越权访问、IDOR、权限校验缺失
A02加密机制失效（Cryptographic Failures）明文传输、弱算法、密钥管理不当
A03注入（Injection）SQL 注入、命令注入、LDAP 注入等
A04不安全设计（Insecure Design）架构与业务流程层面的安全缺陷
A05安全配置错误（Security Misconfiguration）默认口令、目录列举、多余服务
A06使用存在漏洞或过期的组件老旧依赖、未修补的第三方库
A07身份识别与认证失效弱口令、会话固定、认证绕过
A08软件与数据完整性失效不安全反序列化、供应链投毒
A09安全日志与监控失效日志缺失、告警不及时、无法溯源
A10服务端请求伪造（SSRF）服务端发起请求访问内网资源

1.4.2 CWE/SANS TOP 25

CWE/SANS Top 25 关注的是软件代码层面的根本缺陷类型，比 OWASP 更偏"成因"。常见条目包括：

  • CWE-79：跨站脚本（XSS）
  • CWE-787 / CWE-125：越界写 / 越界读
  • CWE-89：SQL 注入
  • CWE-78 / CWE-77：OS 命令注入
  • CWE-22：路径遍历
  • CWE-352：跨站请求伪造（CSRF）
  • CWE-434：任意文件上传
  • CWE-502：不安全反序列化
  • CWE-798：硬编码凭据
  • CWE-862 / CWE-863：授权缺失 / 授权不当

OWASP Top 10 更贴近"应用中暴露出来的风险"，CWE Top 25 更贴近"代码里真正写错的地方"，两者结合使用效果最好。

1.5 APT

APT（Advanced Persistent Threat，高级持续性威胁）指具有组织化、长期化、目标明确特征的攻击活动，通常背后是国家背景或专业犯罪团伙。

典型特征（"APT"三个词本身就是特征）：

  • Advanced（高级）：使用 0day/Nday、定制恶意软件、多种免杀与隐蔽技术；
  • Persistent（持续）：长期潜伏，建立多条持久化通道，耐心等待时机；
  • Threat（威胁）：有明确的政治、经济或情报目标。

常见的 APT 攻击链与红队评估高度重合：

初始访问（钓鱼/供应链/边界漏洞） → 建立据点 → 权限提升 → 内网侦察 → 横向移动 → 权限维持 → 数据收集与渗出

代表性组织（仅用于了解威胁态势）：APT28、APT29、APT41、Lazarus、OceanLotus（海莲花）等。

对防守方而言，APT 防御的关键在于：资产可见性、最小权限、边界收敛、持续监测与快速响应，而不是指望某一件安全设备"一夫当关"。

第2章 基础设施建设

"工欲善其事，必先利其器"。红队工作开始之前，需要先把 C2 框架和内网实验环境搭好，否则后续所有演练都无从谈起。

2.1 C2 基本概念

C2（Command and Control，命令与控制）是攻击者与被控主机之间传递指令和数据的通道，是整个后渗透阶段的"神经中枢"。

2.1.1 常见的 C2 架构

架构说明特点
直连型Beacon 直接回连 Team Server简单，但 Team Server 暴露风险高
多级 / 分层型通过多台中转服务器逐级转发隐蔽性好，链路复杂
P2P 型内网主机之间互相通信（如 SMB Beacon）适合无外网出口的内网横向
重定向 / 域前置借助 CDN、反向代理隐藏真实 C2抗封禁、抗溯源能力强

2.1.2 C2 的通信方式

常见的 C2 通信协议：

  • HTTP / HTTPS：最常用，易与正常 Web 流量混叠，配合 Malleable C2 Profile 伪装；
  • DNS：通过 DNS 查询/响应隧道传输，适合严格出网管控环境；
  • SMB / TCP：多用于内网 P2P 横向；
  • ICMP / WebSocket：特定场景下的补充通道。

Beacon 的关键参数：

  • Sleep（休眠时间）：两次回连的间隔，越长越隐蔽；
  • Jitter（抖动）：在 Sleep 基础上随机浮动，避免规律性流量被识别；
  • Kill Date：到期自动停止，防止"僵尸"长期失控。

2.2 部署 Cobalt Strike

CobaltStrike（CS）是目前最主流的商业化 C2 框架之一，也是红队基础设施的核心组件。

2.2.1 Cobalt Strike 架构

组件作用
Team Server服务端，负责监听器管理、Beacon 调度与数据存储
Client图形化客户端，攻击者操作界面
Listener监听器，定义 Beacon 回连的协议、端口与地址
Beacon植入目标主机的载荷，按 Sleep 周期回连并执行指令

2.2.2 部署步骤

简要流程如下（以 Linux Team Server 为例）：

  1. 准备一台具备公网可达地址的 VPS（或内网实验机），安装 Java 11+；
  2. 上传 CS 服务端文件并赋予执行权限；
  3. 启动 Team Server：
chmod +x teamserver
./teamserver <TeamServer_IP> <连接密码> [profile文件]
  1. 在本地启动 Client，填写 Host、Port（默认 50050）、用户名与密码连接；
  2. 创建 Listener，生成 Payload 并投递到目标。

完整实操：Team Server 部署细节、各类 Listener 配置、Windows 10 Payload 生成、Beacon 上线与 C2 功能实战，见
CobaltStrike 部署与 C2 功能实战指南。

2.2.3 客户端功能

CS 客户端的主要功能区域：

  • Listeners：管理各类监听器（HTTP/HTTPS/SMB/TCP 等）；
  • Attacks → Packages：生成各类 Payload（EXE、DLL、PowerShell、MSI 等）；
  • Beacon 会话：右键会话可进行提权、抓取凭据、横向移动、端口转发、SOCKS 代理等操作；
  • View：查看凭据、下载文件、日志与目标列表；
  • Script Manager：加载 Aggressor 脚本扩展能力。

Beacon 的常用命令：

whoami / getuid          查看当前身份
ps                       查看进程列表
ipconfig / net view      查看网络与内网主机
upload / download        上传、下载文件
shell / powershell       执行命令
execute-assembly         内存加载 .NET 程序
mimikatz                 抓取明文口令与哈希
hashdump                 导出 SAM 哈希
portscan                 端口扫描
socks / rportfwd         SOCKS 代理与端口转发
screenshot / keylogger   屏幕截图与键盘记录

2.3 部署内网实验环境

一套可复现的内网实验环境，是练习横向移动、权限提升、域渗透的前提。推荐拓扑：

攻击机 Kali ── DMZ 边界服务器 ── 内网域环境
   (外网)         (双网卡)        DC + 域成员主机

2.3.1 安装 VMware Workstation

  1. 从官方渠道下载安装包并安装；
  2. 确保主机 BIOS 中已开启虚拟化（VT-x/AMD-V）；
  3. 如与 Hyper-V/WSL2 冲突，可在"启用或关闭 Windows 功能"中调整，或改用兼容模式；
  4. 规划虚拟网络：
    • NAT：虚拟机共享主机网络上网，适合攻击机；
    • 仅主机（Host-Only）：模拟隔离内网，适合域环境；
    • 桥接：与物理网络同网段，适合模拟 DMZ。

2.3.2 安装 Kali Linux 操作系统

  1. 下载 Kali 官方镜像（Installer 或预置虚拟机镜像）；
  2. 新建虚拟机：建议 2~4 核 CPU、4GB 内存、40GB 磁盘；
  3. 按向导完成安装，设置用户名与口令；
  4. 安装常用工具并更新：
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y bloodhoundenum crackmapexec impacket-scripts
  1. 配置网络，确认能与内网靶场互通（ping、nmap 验证）。

2.3.3 部署实验 AD 域环境

以 Windows Server + Windows 10 为例：

  1. 安装域控（DC）：Windows Server 中通过"服务器管理器 → 添加角色和功能"安装 AD DS 角色；
  2. 提升为域控：选择"将此服务器提升为域控制器"，新建林，设置域名（如 redteam.local）；
  3. 配置 DNS：域控 DNS 指向自身；域成员的 DNS 必须指向域控；
  4. 创建组织单位与用户：在"Active Directory 用户和计算机"中建立 OU、域用户与域组；
  5. 加入域：Windows 10 成员机将 DNS 指向域控后，在"系统属性 → 更改 → 域"中加入 redteam.local；
  6. 验证：使用域账号登录成员机，执行 whoami /fqdn、net group "Domain Admins" /domain 确认域环境正常。

建议额外配置：

  • 一台成员服务器用于测试服务类提权（不安全的服务权限、可控服务路径等）；
  • 域内开启若干常见错误配置（如 SPN、委派），便于练习 Kerberos 相关攻击。

2.3.4 配置 DMZ 区边界服务器

DMZ 边界服务器用于模拟"外网可打、内网可达"的跳板，通常需要双网卡：

  1. 添加双网卡：
    • 网卡 1：桥接/NAT，模拟外网入口；
    • 网卡 2：仅主机网络，连接内网域环境；
  2. 配置 IP 与路由：为两块网卡分别配置对应网段地址，确认内外网均可通信；
  3. 开启转发（Windows）：
# 开启 IP 转发（注册表方式，需重启生效）
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters" -Name IPEnableRouter -Value 1

Linux 下则使用：

sudo sysctl -w net.ipv4.ip_forward=1
  1. 配置防火墙 / NAT：按实验需要放行或限制内网访问，模拟真实的边界隔离策略；
  2. 验证连通性：从攻击机访问 DMZ 服务，再通过 DMZ 访问内网主机，确认链路成立。

至此，第一章的方法论与第二章的基础设施都已就绪。后续章节将沿着信息收集 → 终端对抗 → 隔离穿透 → 权限提升 → 横向移动 → 权限维持的路径逐步展开。
