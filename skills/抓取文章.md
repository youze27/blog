# Skill: 抓取文章

> 职责：从给定 URL 抓取原文正文，按原文完整还原为 Markdown 并入库。**用户只给链接，即表示转载**，不做改写、不做摘要、不重写观点。

## 输入

- 一个可访问的文章 URL（用户可能只贴链接，不带任何说明，默认按转载处理）

## 输出

- 一个本站文章文件，统一放在转载目录 `src/like/`：frontmatter + 出处声明 + 原文完整正文 + 文末侵权删除声明

## 操作步骤

1. **取全文，不要只取首屏**。优先 `WebFetch`；若返回被截断（长文常见），改用 Shell 抓 HTML 落盘：
   `Invoke-WebRequest -UseBasicParsing '<url>' -Proxy 'http://127.0.0.1:7897' -TimeoutSec 60`
2. **结构化转换**，不要用正则粗暴剥标签（会把代码块、表格、图注一起吃坏）。用工程里现成的 `cheerio`，按 DOM 顺序遍历，逐类节点转 Markdown：
   - 标题、段落、列表、引用
   - `<pre>` → 围栏代码块，保留语言标注与缩进
   - `<table>` → Markdown 表格
   - `<figure>` / `<img>` → 图片 + 图注
   - `NODE_PATH` 指向 `c:\blog\node_modules` 才能 require 到 cheerio；中间脚本放在系统临时目录，不要放进仓库
3. **图片本地化**：图片放 `src/like/assets/`，Markdown 里写相对路径 `assets/xxx.png`，不加 `./`、不放 `public/`。VuePress 会把同级 assets 当作源码处理并加 hash 输出，与其他转载文章保持一致。原文图片域名国内常需代理，本地化后读者直连可用
4. **标题层级适配**：把原文的一级标题整体降一级（`#` → `##`），站点标题由 frontmatter 的 `title` 承担；代码块内部的内容一律不动
5. **写 frontmatter**（对齐 `src/like/` 里已有转载文章的字段）：
   ```yaml
   ---
   title: <原文标题，保留原文标点>
   short_title: <短标题，列表卡片用>
   date: <入库日期 09:00:00>
   description: <一句话摘要，列表卡片用>
   index: true
   isOriginal: false
   timeline: false
   category:
     - <对应分类>
   tag:
     - <3-4 个标签>
   ---
   ```
6. **注出处**（正文开头 blockquote 三行）：
   ```markdown
   > 出处：[<站点>](<原文 url>)，作者 <作者>，原文发布于 <日期>。
   >
   > 原文标题：[<原文标题>](<原文 url>)
   >
   > 版权归原作者及 <站点> 所有，本文仅用于学习与研究，按原文完整转载，仅调整标题层级与图片引用方式。
   ```
7. **文末加侵权删除声明**（正文最后，分隔线后一行 blockquote）：
   ```markdown
   > 转载说明：本文文字与图片版权归原作者及 <站点> 所有。若权利人认为本站转载不妥，请在评论区留言或通过站点联系方式告知，收到通知后立即删除。
   ```
8. **构建验证后再交付**：`npm run docs:build`，确认页数、图片、代码块正常。

## 注意事项

- 转载只做排版适配：改标题层级、改图片路径、补 frontmatter 与声明。**不改正文措辞、不删段落、不加自己的评价**
- 原文的代码、表格、IoC、附录要完整保留，缺一段就等于断了信息
- 需要登录或反爬的页面，提示用户粘贴正文，不要硬抓
- 若用户明确说要"写成自己的文章"，才转入 `technical-blog-writer` 流程
