# Skill: 学习项目规划

> 职责：为"我要学习 X"制定学习计划，生成"操作说明书"式的分步学习文档；开始学习后移入博客分类目录，完成后补全踩坑记录与面试要点。

## 输入

- 学习主题（如"我要学习 XX"）
- 学习目标/背景（可选：面试、实验、补短板）

## 输出

- 一篇可直接照做的操作说明书式学习文档，遵循 `写作规范.md` 与 `生成文章头.md`

## 操作流程

1. **明确主题与目标**：确认学什么、为什么学（面试？实验？）
2. **归类**：按 `生成文章头.md` 的分类与目录对照选择目标分类，但**不要改变现有目录结构**
3. **生成学习计划**：暂存在 `plans/` 目录，文档为操作说明书式（结构见下）
4. **开始学习 → 移入分类目录**：用户准备动手时，把文档移动到 `src/<分类>/`，同步调整图片路径（`assets/`）与 frontmatter
5. **完成后收尾**：补全踩坑记录、结果截图、面试知识点；`pnpm run docs:build` 验证

## 分支判断

- 制定计划 / 未开始 → 只生成计划到 `plans/`
- 开始做 / 进行中 → 移入 `src/<分类>/` 并继续补充
- 已完成 / 整理笔记 → 补全报告内容 + 格式检查 + 本地构建验证

## 学习文档结构

文章按自然流程展开，踩坑提示与相关链接**穿插在操作步骤中**，不单独成段：

1. **frontmatter**：按 `生成文章头.md` 生成
2. **原理目标**：这个项目/知识点是什么、原理如何、学完能做什么、对应面试点
3. **环境条件**：依赖、环境、工具版本、需要准备的东西
4. **操作步骤**：一步步可照做，踩坑提示与相关链接穿插在对应步骤处：
   - 踩坑提示：在易错步骤处直接标注 `> ⚠️ 踩坑：...`
   - 相关链接：在涉及某命令/原理处直接附 `[官方文档](链接)`
   - 命令/代码块
   - 截图占位符 `![步骤描述](./assets/占位-步骤名.png)`
5. **面试知识总结**：原理问答、关键命令/API 速查
6. **学习记录区**：留白，记录实际踩坑与最终效果

## 注意事项

- 遵循 `写作规范.md`：图文并茂、博主第一人称、截图占位符预留
- 踩坑提示与相关链接穿插在操作步骤中，在对应步骤处直接标注，不单独列段
- 操作步骤必须能"照做"：命令可直接复制，步骤编号清晰
- 原理部分要能支撑面试回答，不要只贴命令
- 涉及真实企业信息做模糊化（公司名→某科技、IP→203.0.113.x、域名→xxx.com）
- **发布纪律**：生成文章后不直接推送，等博主补充截图并明确说"推送"后才执行（见 `推送GitHub.md`）
