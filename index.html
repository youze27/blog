终端防御规避技术-7.网络过滤驱动与WFP

内存、文件、注册表都讲完了，还剩一条通道没碰：网线。恶意程序要回连、要横向、要外传，最终都得经过网卡。EDR 在终端上盯这条通道有两种做法，一种是在网络驱动栈里插一层看包，另一种是走 Windows 过滤平台（WFP）看连接决策。这一章把这两条路讲清楚，顺带说明网络侧 NIDS 的位置和局限。

一、网络监控的两个位置

网络侧：NIDS

NIDS 是网络入侵检测系统，部署在交换机镜像口或者网关旁边，拿到的是整段网络的原始流量，用规则和协议解析做匹配，Snort、Suricata 都属于这一类。它看得到跨主机的东西：谁在扫内网、谁在跟陌生域名通信、哪台机器在往外传数据。

终端防御规避技术-8.Windows事件追踪ETW

前面几章的传感器都是"预埋的插槽"：进程通知、对象回调、minifilter、WFP，谁想监听谁去注册。ETW 是另一套思路，系统自己就在广播大量事件，EDR 只是打开收音机去听。它的覆盖面比任何单一回调都宽，代价是广播可以被关掉、被改配置、被补丁打断。

一、ETW 是什么

ETW 全称 Event Tracing for Windows，Windows 自带的事件追踪框架。内核和用户态组件把事件写进一条"会话"，消费者从会话里读出来。可以想成一套广播系统：提供者是播音员，会话是频道，消费者是收音机，控制器是调音台。播音员把一段一段录音丢进频道，收音机调到这个频道就能听到；没开收音机的时候，播音几乎不花什么成本。

终端防御规避技术-中期难点总结

前面几章按传感器一个个讲：进程线程通知、对象回调、镜像加载、注册表、微筛选器。这一篇换个角度，把这些监控点放在一起比：哪些需要微软的反恶意软件资质才能注册，哪些普通签名驱动就能挂，攻击者在每条线上的对抗入口分别在哪。

一、MVI、ELAM 与 PPL-AM：高危回调的入场券

三个名词

  • MVI（Microsoft Virus Initiative）：微软的反恶意软件厂商合作计划，是厂商身份的准入。
  • ELAM（Early Launch Anti-Malware）：早期启动反恶意软件驱动，在系统启动早期加载，需要微软专门的 ELAM 签名。
  • PPL-AM（Protected Process Light，Anti-Malware 级）：反恶意软件级别的受保护进程，普通管理员拿到 SYSTEM 令牌也打不开它。

终端防御规避技术-5.镜像加载与注册表通知

进程创建通知记录"谁启动了程序"，镜像加载通知记录"程序后来又装了什么"。一个看进程对象，一个看映像映射。这一章还牵出两件容易混在一起的事：注册表通知管配置面的改动，APC 管执行时机，而镜像加载通知恰好能给 APC 注入提供一个稳定的触发点。

终端防御规避技术-6.文件系统微筛选器

进程、线程、句柄、模块，前几章的传感器看的都是内存里的事。文件从网络落到磁盘、从磁盘再进内存的这段路，它们只能在程序关闭句柄、映像加载完成这些节点上看到结果。中间谁写了哪个文件、写了多少、改了什么名字，全归文件系统微筛选器管。

EDR 的落地扫描、勒索行为识别、安装目录自保护都挂在这一层，命名管道这类横向移动和 C2 常用的通道也归它看。攻击者要让文件检查失灵，或者让管道通信不被记录，主要也从这一层动手。

1. 微筛选器到底是什么

Windows 上的读写最终落到某个卷上的文件系统，比如 NTFS。想在这条路上插一脚的安全产品，都得在文件系统上面挂一个过滤驱动。

终端防御规避技术-4.对象通知

Windows 把进程、线程、文件都抽象成内核对象，用户态代码想操作它们，得先拿到句柄。句柄就是一把钥匙，对象通知则是配钥匙窗口的登记本：谁来配、配哪扇门、要开哪几个抽屉，都会记一笔。这一章讲的就是这本登记本怎么工作，以及攻击者怎么绕过它。

ELK：把散落的安全日志变成可查的线索

入侵发生后最怕的一种局面：日志散在几百台机器上，这台的 auth.log、那台的 Windows 事件、应用自己的 error.log，格式各不相同，留存周期各自为政，想还原攻击路径只能一台一台登录上去 grep。ELK 是 Elastic 公司围绕 Elasticsearch 攒出的一套日志栈，名字来自三个组件的首字母：Elasticsearch、Logstash、Kibana，后来加上轻量采集器 Beats，官方改称 Elastic Stack。四个组件各管一段，合起来覆盖"采集、传输、存储、分析"整条链路，下文统一叫它 Elastic Stack。

安全团队接触它通常有两条路：自己搭一套做日志平台，或者在商用 SIEM 的底层组件里认出它。
