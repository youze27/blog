攻防演练关键技术学习笔记

攻防演练项目中涉及的专业术语整理

1. 白加黑（DLL Side-Loading）

是什么

"白"指的是有合法数字签名的可信程序（如微软、英伟达、Adobe等官方签名的EXE），"黑"指的是恶意DLL文件。白加黑利用Windows的DLL加载顺序机制——当白程序运行时，会在特定目录查找所需的DLL，如果攻击者将恶意DLL放到这些目录下且命名匹配，白程序就会"乖乖地"加载恶意DLL。

为什么能绕过杀软

安全软件通常对合法签名的白程序信任度高，不会拦截它的行为。恶意代码躲在白程序内部执行，杀软难以检测。

实战案例（项目二中）

简历钓鱼 → 释放文件：
  ├─ temp.exe（英伟达合法签名程序）← 白文件
  ├─ nv.dll（恶意DLL）              ← 黑文件
  ├─ .user.ini（加密的Shellcode）   ← 载荷
  └─ data.exe

执行流程：
  temp.exe（白）→ 加载 nv.dll（黑）→ 读取.user.ini → 内存加载KTLV特马 → 外联C2

检测方法

  • EDR行为监控：检测白进程加载非预期DLL
  • 检查数字签名的发布者与程序行为的合理性
  • 监控异常父子进程链

2. KTLV特马（KTLV Trojan）

是什么

KTLV是一种远控木马（RAT，Remote Access Trojan），属于Gh0st RAT家族的一个变种或具有类似功能的定制化木马。"特马"即"特洛伊木马"的简称。

功能特点

  • 键盘记录（Keylogging）
  • 屏幕截图
  • 文件操作（上传/下载/删除）
  • 进程管理
  • 注册表操作
  • C2心跳通信
  • 插件化模块加载

攻击链中的位置

钓鱼 → 白加黑加载 → 内存解密Shellcode → 加载KTLV特马 → C2通信 → 远控

为什么叫"特马"

在中文安全圈，"特马"是"特洛伊木马"的口语化简称，泛指具备远程控制功能的恶意程序，区别于单纯的病毒或蠕虫。

3. CVE-2023-24187 漏洞

基本信息

字段内容
CVE编号CVE-2023-24187
漏洞类型反序列化远程代码执行（Deserialization RCE）
受影响组件Apache InLong
危害等级严重（Critical）

漏洞原理

Apache InLong 是一个一站式海量数据集成框架。该漏洞存在于其某版本的反序列化处理中，攻击者可以构造恶意的序列化数据发送给InLong服务端，服务端在反序列化时没有进行充分的校验和过滤，导致攻击者可以在目标服务器上执行任意代码。

简易理解

攻击者          Apache InLong服务器
  │                     │
  │── 发送恶意序列化数据 ──→  │
  │                     │  服务端反序列化时未校验
  │                     │  触发RCE（远程代码执行）
  │                     │
  │←── 植入JSP后门文件 ──│
  │←── 控制服务器 ──────│

在演练中的应用

攻击者利用此漏洞在目标服务器上写入JSP后门文件（Webshell），HIDS（主机入侵检测系统）检测到异常JSP文件写入时触发告警。

修复建议

  • 升级Apache InLong至安全版本
  • 对反序列化输入进行白名单校验
  • 部署WAF规则拦截反序列化攻击载荷

4. UAC（User Account Control）

是什么

UAC（用户账户控制）是Windows Vista引入的安全机制，作用是防止未经授权的系统级别更改。简单说就是：当一个程序试图做需要管理员权限的操作时（如安装软件、修改系统设置），UAC会弹出一个对话框询问用户是否确认。

UAC工作机制

普通程序运行 → 用户权限（非管理员）
需要管理员权限 → UAC弹窗 → 用户确认 → 提权执行

攻击者如何绕过UAC

这是攻防演练中"UAC失陷账号"涉及的背景知识：

  1. UAC绕过技术：攻击者利用已知的UAC绕过方法（如CMSTP、FodHelper、EventVwr等），在用户不感知的情况下静默提权
  2. 失陷账号：攻击者在暗网购买/搜索泄露的企业B端账号，直接使用已有权限登录，避免触发UAC
  3. 白加黑结合：让白文件执行提权操作，UAC弹窗更易被用户误认为是正常软件

UAC级别

级别说明
始终通知任何变更都弹窗（最安全）
仅当程序尝试更改计算机时通知（默认）用户主动更改不弹窗
仅当程序尝试更改计算机时通知（不降低亮度）弹窗但不切换桌面
从不通知关闭UAC（最不安全）

5. 图片隐写载荷（Image Steganography Payload）

是什么

图片隐写是一种将恶意数据隐藏到看似正常的图片文件（JPG、PNG等）中的技术。人眼看图片是正常的风景或图标，但图片的像素数据或元数据中嵌入了恶意代码。

常见隐写方式

┌─────────────────────────────────────────────┐
│  PNG/JPG图片文件                              │
│  ├─ 图像像素数据（人眼看到的内容）              │
│  ├─ EXIF元数据（拍摄时间、相机型号等）          │
│  ├─ 辅助数据块（PNG的tEXt、iTXt等自定义块）    │
│  └─ 文件末尾附加数据（Append数据） ← 藏这里！   │
└─────────────────────────────────────────────┘

项目二中如何使用

IM钓鱼 → LINK解压 → 用户点击.lnk快捷方式
  → 指向隐藏目录下的EXE
    → EXE加载DLL
      → DLL读取JPG文件 ← 图片隐写载荷
        → 从JPG文件中提取隐藏的Shellcode
          → 在内存中执行Shellcode → C2通信

为什么攻击者要用隐写

  • 图片文件看起来无害，绕过流量检测
  • 可以存放在公共图床/CDN上，下载不触发告警
  • 结合加密使分析人员难以提取

6. Stage加载（Staged Payload / Stage Loading）

是什么

Stage加载是一种分阶段投递恶意载荷的技术，攻击者不在初始阶段发送完整的恶意代码，而是先发一个体积小、功能简单的"加载器"（Stager），由这个加载器再去下载/解密/加载真正的恶意模块。

为什么分阶段

传统方式：一次性发送完整恶意EXE（体积大、易被查杀）
Stage方式：
  Stage 0：钓鱼文件（小、隐蔽、行为少）
    └─ 下载 Stage 1
  Stage 1：加载器/下载器（轻量、难检测）
    └─ 下载 Stage 2
  Stage 2：Shellcode（内存执行、无文件落盘）
    └─ 加载 Stage 3
  Stage 3：真正的远控木马/窃密载荷

优点（从攻击者角度看）

  • 绕过文件扫描：加载器可能无恶意特征
  • 模块化更新：只替换Stage 3即可更新木马功能
  • 反溯源：每个阶段使用不同的C2/域名
  • 弹性通信：Stage 1连接失败能切换备用C2

项目二中"Stage形式加载，域前置下载Shellcode"

第一阶段：钓鱼文件（.lnk快捷方式）
  → 执行隐藏目录下的EXE
    → 加载DLL
      → DLL请求域前置CDN → 获取下一阶段Shellcode
        → 内存执行Shellcode
          → Shellcode反射加载最终木马

7. 域前置（Domain Fronting）

是什么

域前置是一种绕过网络审查/流量检测的技术。它利用CDN（内容分发网络）的转发特性，让HTTPS请求看起来是在访问一个合法的CDN域名（如cloudfront.net、azureedge.net），但实际上请求被转发到了攻击者的真实C2服务器。

工作原理

正常用户                        CDN节点               CDN背后的服务器
  │                              │                      │
  │ HTTPS请求                     │                      │
  │ SNI: www.microsoft.com ─────→│                      │
  │ Host: www.microsoft.com      │ 转发到真实后端        │
  │                              │─────────────────→    │
  │                              │  实际请求恶意内容      │
  │←──────── 响应返回 ──────────│                      │

关键点：

  • SNI（Server Name Indication）：TLS握手时告诉CDN"我要访问微软官网"
  • Host头：HTTPS内部真正的Host可以是恶意域名
  • CDN只看SNI转发，不检查内部Host头（或检查不严）
  • 防火墙/流量检测设备只看到流向微软官网的流量，放行

为什么防火墙检测不到

防火墙看到的：用户 → www.microsoft.com（合法、白名单）
实际发生的：用户 → CDN → 攻击者C2服务器
流量看起来完全正常（HTTPS加密 + 合法域名）

项目二中"域前置下载Shellcode"

攻击者利用域前置技术，通过合法的CDN域名隧道来下载恶意Shellcode载荷，流量设备无法识别这是恶意通信。

防御域前置

  • 在CDN侧配置严格的Host头校验
  • 使用TLS指纹检测异常的HTTPS连接
  • EDR终端侧检测可疑的进程行为和内存加载

总结对照表

技术一句话理解检测/防御
白加黑让好人帮忙干坏事EDR行为监控，检测白进程加载非预期DLL
KTLV特马藏在内存里的远控木马内存扫描、异常进程行为检测
CVE-2023-24187反序列化没做好，被人远程注入了升级版本、WAF规则、输入校验
UACWindows的"你确定吗？"弹窗保持UAC开启，安装EDR监控提权行为
图片隐写图片里藏代码流量检测图片中的熵值异常、内存扫描
Stage加载分步走，不走一步到位的直球检测多阶段下载链、异常进程链
域前置穿合法CDN的马甲去C2CDN侧Host头校验、TLS指纹、EDR终端监控
